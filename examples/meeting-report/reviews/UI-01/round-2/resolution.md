# UI-01 라운드 2 판정

**Chrome 자동화 39개 통과. 보조기술 검토 보류.**

- A/B 독립 보고서를 수신했다. 두 보고서의 초점 표현 지적을 받아 일반·320px 실패 시안에 초점 표시를 추가하고, 스펙 보조 문서인 디자인 JSON에 사용자가 초점을 다른 곳으로 옮기지 않았을 때의 복구 조건을 명시했다. 이 마지막 시안 정정은 작업자가 두 위치에서 확인했다.
- S-39는 Tab과 Enter로 첫 완료 요청을 보내고, HTTP 500 후 같은 행 오류·버튼 활성·초점 복귀·라이브 영역 메시지를 확인한다. Enter 재시도 후 완료 표시, 오류 제거, 해당 항목 POST 총 2회를 확인했다.
- 화면 낭독기가 오류 안내와 다음 행동을 실제로 전달하는지는 미확인이다. QA가 실제 화면 낭독기로 같은 시나리오를 실행하고 브라우저·낭독기·들린 메시지를 기록하면 재판정한다.
- 현재 FSD 승인 및 검증 상태는 이전 버전의 이력이다. 변경 작업본의 재승인과 검토 증거 연결은 별도다.

실행 명령 `node node_modules/@playwright/test/cli.js test e2e/UI-01/ --workers=2 --output=/private/tmp/fsd-ui01-recovery`.

## 2026-11-20 Safari + VoiceOver 재확인

- 대상: 라운드 2에 기록된 작업본. 실제 예제 서버에 요청을 전달하는 루프백 테스트에서 첫 완료 POST만 HTTP 500을 반환했다.
- 결과: Safari의 접근성 트리에서 최종 완료 상태와 성공 라이브 문구를 확인했다. 테스트 서버 로그에는 같은 항목에 대한 POST 2회가 남았다.
- VoiceOver 활성화와 자막 패널 설정은 확인했으나, 컴퓨터 제어 도구가 VoiceOver 앱의 자막 표면을 조회할 때 시간 초과됐다. Safari 접근성 트리는 실제 낭독 증거로 계산하지 않는다. 실패 문구의 낭독은 보류다. 테스트 후 VoiceOver를 원래의 끔 상태로 복원하고 테스트 서버와 탭을 닫았다.
- 코드 탐색에는 FSD 저장소의 Graft 그래프에서 `graft grep completeTask -i`를 사용했다. 권한으로 인덱스 갱신이 생략되어, 실패 주입과 재시도의 기준은 현재 소스와 S-39를 직접 대조했다.
